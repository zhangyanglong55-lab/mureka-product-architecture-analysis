Mureka 产品架构拆解｜第一轮

一句话：Mureka 是一个以“歌曲生成”为中心、向参考音频、可复用歌手角色、画面配乐和音乐视频延伸的 AI 音乐工作台；访客可先看见大部分创作参数，真正执行、保存和管理时再进入登录、会员与金币门槛。

采集日期：2026-08-18｜范围：Mureka 中国站公开页面、访客态交互、官方公开资料｜未生成、未上传、未购买、未消耗免费次数或金币。

三分钟看懂证据流程架构风险术语

0. 三分钟看懂

输入什么

一句灵感，或歌词＋风格＋人声性别＋歌名；也可附参考音频、视频或图片。

系统做什么

把创作意图组织成模型可执行条件，异步生成歌曲；还可以将已有歌曲和角色、背景、情绪组合成音乐视频。

得到什么

歌曲、纯音乐、画面配乐或音乐/歌词视频；作品会进入曲库或工作区——但访客态未实际验证写入。

用户决定什么

选简易/自定义/配乐，是否用参考曲或歌手角色，是否继续登录、升级会员或消耗额度。

最大风险：页面同时显示“0 金币”“1 次免费”，但受保护动作会要求登录。访客很难判断免费次数是否真实可用、何时扣费、上传参考音频是否会被他人使用。

用大白话描述这套产品

它像一个“会作曲的线上录音棚”。新手只要聊天说想法；懂音乐的人可以精确填歌词、风格和歌手；做视频的人可以先交画面，再让系统配乐。生成完成后，用户还能继续做 MV、歌词视频或深度编辑。

17. 当前架构 As-Is 与建议架构 To-Be

As-Is｜当前能确认

  • 三条创作入口覆盖新手、专业控制和画面配乐。
  • 参考、Remix、角色库和视频工作区构成从歌曲到衍生内容的链路。
  • 官方/上传/收藏分栏支持资产复用。
  • 登录、会员、Pro/Premier、金币形成权限与商业化门。
  • 任务、版本、重试和完成校验在访客态不可见。

To-Be｜建议补齐

  • 一个统一状态事实源，同时驱动聊天、表单、曲库与工作区。
  • 生成前明确预计金币、冻结额、生成份数、时长和取消规则。
  • 资产存在＋上下文写入＋质量校验＋确认记录共同构成完成门。
  • 用户改歌词/角色/参考后，自动标记依赖资产失效并局部重算。
  • 任务幂等、失败释放额度、中断传播、全链路追踪。
  • 授权说明前置，私有素材默认不允许他人使用。

22. 结论

Mureka 的产品骨架已经相当完整：用公开内容激发需求，用三种入口覆盖不同用户，再通过参考曲、角色和视频把一次“生成歌曲”延伸为可持续创作链。当前最值得改善的不是再增加按钮，而是让用户在上传、生成和重试前清楚知道三件事：素材会怎么用、这次会花多少、什么时候才算真的完成。

本报告不包含隐藏思维链、System Prompt、Cookie、Token、账号敏感信息或未经证实的后端实现。官方资料只用于确认公开能力边界，未把 API 文档直接等同于消费端内部架构。
